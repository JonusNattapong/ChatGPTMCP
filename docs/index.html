Technical reference

ChatGPTMCP Hybrid

A compact ChatGPT-facing surface over machine operations, reasoning tools, reusable skills, and persistent memory. ChatGPT plans the work; toolpy composes the underlying capabilities.

Hybrid surface

Legacy mode advertises the low-level MCP tools directly. Hybrid mode keeps those capabilities behind a controlled Python runtime and advertises only toolpy and capability_registry to ChatGPT. This reduces tool-selection noise while preserving access to the full capability set.

Public toolResponsibility
toolpyExecutes model-generated Python in a persistent, controlled runtime. The cell can inspect its catalog, call approved capabilities, compose multiple operations, and return a structured result.
capability_registryReturns metadata for the capabilities available behind toolpy, grouped as coding, think, skills, and memory. It does not execute a capability.

Runtime contract

allow_tools

Read-only capabilities are available by default. Mutating capabilities must be explicitly declared on the outer toolpy request.

session_id

Names a persistent IPython namespace. Imports, variables, and generated helpers can survive across calls until reset, eviction, restart, or timeout termination.

max_calls

Bounds the number of nested MCP capability calls from one cell.

timeout_ms

Bounds cell execution. A timeout terminates the session to guarantee cleanup.

max_output_bytes

Bounds captured stdout, stderr, display output, and structured results.

catalog = await describe()
status = await tools.machine_status({})
result({"catalog": catalog, "status": status})

Authority requirement: hybrid mode requires --dangerously-open-machine. The persistent Python runtime runs with the operating-system permissions of the MCP worker. Use the ordinary bounded tool surface when you need workspace-only authority, or place the bridge inside an external sandbox.

Attach capability providers

Hybrid mode can attach local provider directories behind toolpy. The current CLI accepts Skill Hub, ThinkForge, and OurBook memory providers.

node dist/index.js \
  --dangerously-open-machine \
  --tool-surface hybrid \
  --skill-hub-dir D:\Projects\Github\chatgpt-skill-hub \
  --thinkforge-dir D:\Projects\Github\ThinkForge-MCP \
  --memory-dir D:\Projects\Github\ourbook

Architecture

Streamable HTTP enters the MCP server directly. Tunnel stdio enters through apps/server/src/supervisor.ts, which isolates apps/server/src/index.ts in a worker process and can restart and reinitialize that worker after a crash or hard request deadline. Inside the worker, the registry validates tool names and arguments before policy, preconditions, idempotency, and handlers can touch the host.

Architecture reference

The tunnel is transport plumbing. The MCP server is not tied to a specific ChatGPT UI and can serve any compatible MCP client.

Tool surface

In legacy mode, the server exposes purpose-built tools for host operations. In hybrid mode, the same capabilities stay callable from toolpy but are not all advertised directly to ChatGPT.

Concurrency guard

File reads return a SHA-256 digest. Writes can pass expected_sha256, converting a stale update into PRECONDITION_FAILED instead of silently overwriting a newer edit.

Stable failures

CodeMeaning
INVALID_ARGUMENTMissing, invalid, or out-of-range input.
PATH_DENIEDWorkspace boundary, symlink escape, or OS permission block.
PRECONDITION_FAILEDThe file changed after it was read.
AMBIGUOUS_MATCH / NO_MATCHA text edit cannot be applied safely.
TIMEOUT / NETWORKAn external command or network operation did not complete.

Safety model

Workspace-only mode keeps file tools, search, shell working directories, and patches under --root. Symlink and junction escapes are rejected.

Unrestricted mode uses --dangerously-open-machine and allows absolute paths plus arbitrary shell reach with the authority of the current OS account. Hybrid mode requires this authority because it depends on the persistent Python runtime.

This is an administrative bridge, not a hostile multi-tenant sandbox. Only connect clients and tunnels that you trust with the same authority as the OS account running the server.

Network and image safeguards

save_image_from_url accepts HTTPS only, rejects private and local network destinations, limits redirects, sends no caller cookies or authorization headers, and validates supported image signatures before writing.

Transport

Use supervised stdio for the tunnel or Streamable HTTP as an alternate transport.

node dist/index.js --http --http-port 8787 --root D:\Projects\Github

/healthz reports process liveness. /readyz reports readiness. MCP traffic is served at /mcp. The dependency-free /ui page reads redacted audit events from /ui/audit.

Binding HTTP beyond loopback requires a bearer token, which also protects the UI endpoints.

node dist/index.js --http --http-host 0.0.0.0 --http-token "<secret>" --root D:\Projects\Github

Operations

Use managed processes for servers and watchers. Process metadata and bounded logs are persisted under .chatgpt-machine/, so a restarted MCP worker can recover inspection and stop operations.

chatgpt-local setup
chatgpt-local up
chatgpt-local status
chatgpt-local restart
chatgpt-local down
chatgpt-local doctor
chatgpt-local check
chatgpt-local config show
chatgpt-local version

Local runtime settings live in Git-ignored .chatgpt-machine/config.json. chatgpt-local use <path> persists the active workspace. Status reports the live and configured roots so restart requirements come from worker state rather than assumptions.

Multi-machine gateway

Allowlisted Streamable HTTP nodes live in Git-ignored .chatgpt-machine/machines.json. Selectors can be an id, name, hostname, alias, IP address, or host:port. Arbitrary URLs supplied by tool callers are rejected. Proven read-only routing is separated from approval-gated remote mutation.

macOS, Ubuntu, and WSL

The MCP server supports macOS, Ubuntu, and Ubuntu WSL with Bash as the default shell and POSIX process termination. WSL controls its Linux environment, not arbitrary native Windows processes.
